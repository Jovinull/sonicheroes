Scope

What this project is, and what it is not

It is

  • Hand-written C, C++ and inline assembly source
  • Verified byte for byte against the retail main.dol and all 17 REL modules
  • A non-commercial study and preservation effort
  • Checked by CI: every change rebuilds the DOL and every REL and compares their SHA-1
  • Open source under the MIT license (our code only)

It is not

  • A playable game, a port, or a download of the game
  • Shipping any ROM, disc image or game asset
  • Shipping original binary code or assembly extracted from the disc
  • Affiliated with or endorsed by SEGA
  • Monetized: no ads, no donations, no paid builds

You need your own legally obtained copy of the game to build anything. A build is only useful to somebody who already owns it.

Method

How a matching decompilation works

The goal is not code that merely behaves like the game. The goal is source that, compiled with the original toolchain, produces the exact same bytes as the disc.

Byte for byte

Each function is rewritten until its compiled output is identical to the original, checked in objdiff. Anything less does not count as matched.

Original toolchain

The game was built with Metrowerks CodeWarrior. The same compiler versions are downloaded at build time (and run through wibo on Linux and macOS). No compiler binaries live in the repository.

Verified on every change

The disc ships no .map file, so names and file boundaries are worked out from evidence. Every push rebuilds main.dol and all 17 RELs and checks their SHA-1 against the retail disc.

Why

Why decompile Sonic Heroes?

Preservation

Sonic Heroes was released in 2003 for GameCube, PlayStation 2, Xbox and PC. Readable source is the most durable record of how a game actually works, long after the hardware is gone.

Understanding

Physics, the three-character formation system, stage objects and RenderWare rendering become documented code that anyone can read, instead of guesses.

A foundation

A complete matching decompilation is what fan ports, mods and bug-fix projects are usually built on. This repository only reproduces the original game; what others build on it later is up to them.

Transparency

AI-assisted, verified by bytes

Language models help write parts of this decompilation, and we say so openly. They never decide what counts as done: a function is only marked as matching when its compiled bytes are identical to the original in objdiff, and CI rebuilds and hashes the whole game on every change.

That check cannot be fooled by code that only looks right. Code that does not reproduce the retail instructions, data and relocations exactly is simply not merged as matching.
